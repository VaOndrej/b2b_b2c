0 · Nápad (M·migrator): typ existující definice metapole nejde změnit — MetafieldDefinitionUpdateInput nemá pole type (ověřeno proti schématu 2026-04). Jediná cesta je záloha → smazat definici → založit s novým typem → převést a vrátit hodnoty. Matrixify tohle neřeší, protože přesouvá data, neřídí schéma. V migratoru: examples/reference-migrations/hotfixes/legacy-utils/migrate-metafield-type.mjs (journal na disku, resumovatelný restore) + scripts/audit.mjs, scripts/rename-metafield-values.mjs, scripts/backfill-metafield-values.mjs. Katalog pastí je migration-fixes sekce C a D.

  1. Klon: rsync z apps/_template/ (standardní vyloučení dle README), přejmenovat, npm install, npm run config:link -w won-schema.
  2. Core modul: packages/core/src/schema/convert.ts — convertValue(raw, fromType, toType) jako čistá funkce pro dvojice typů (text ↔ rich_text ↔ list.*, number, boolean) s explicitním UnsupportedConversion místo tichého průchodu; + planMigration({definition, values, targetType}) vrátí seznam nekonvertovatelných hodnot před zápisem. + node:test na každou dvojici typů a na odmítnutí neznámé konverze.
  3. Plocha: pouze Admin (App Home). Žádná Theme App Extension ani Function — appka nesahá na storefront. Polaris průvodce: výběr definice → náhled dopadu (kolik hodnot, kolik se nepřevede) → potvrzení → job s progressem.
  4. Data — kritické: Prisma SchemaJob { shop, ownerType, namespace, key, fromType, toType, phase, startedAt, completedAt } + SchemaJobValue { jobId, ownerId, originalValue, restoredAt }. Záloha hodnot i metadat definice (description, pin, access, capabilities) musí být commitnutá v DB dřív, než se zavolá metafieldDefinitionDelete — jinak přijde merchant o data. Job je resumovatelný podle phase, worker na bulkOperationRunQuery pro čtení a metafieldsSet po 25 pro zápis.
  5. Produkty pro testy: sdílený katalog nestačí — potřeba vlastní seed definic won-e2e-schema.* na simpleA/simpleB (idempotentně zakládané a mazané testem), protože scénář je ze své podstaty destruktivní. Produkty samotné se nemutují.
  6. Admin UI: seznam definic s počtem hodnot a varováním u typů, kde konverze ztrácí strukturu; historie jobů se stažením zálohy jako JSON; tlačítko „obnovit ze zálohy“.
  7. Testy: těžiště v unit testech konverzí a v integračním testu proti dev storu, který ověří, že po pádu uprostřed jobu --resume doběhne do stavu s původním počtem hodnot. Browser E2E jen na Polaris průvodce.
  8. Gate: test:unit, typecheck, build (-w won-schema) + npm run validate:shopify.
